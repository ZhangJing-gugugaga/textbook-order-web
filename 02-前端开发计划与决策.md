## 2. 环境与部署约定（E4 锁定 + Q13/Q14/Q5 复审细化）

- **Web API 一律相对路径**：开发环境 Vite proxy 把 `/api` 转发到本地后端；生产环境 Nginx 同域反代 `/api` → Spring Boot。**代码零域名/IP 硬编码**，移交学校重新部署时前端零改动。
- **子路径部署（Q13）**：moonzj.com 根域继续运行已有服务，本系统部署于 `/textbook/` 子路径——
  - Vite `base='/textbook/'`（local 环境为 `/`，经环境变量区分）；
  - Router `createWebHistory('/textbook/')`；
  - Nginx：`location /textbook/` → SPA 静态目录 + `try_files $uri $uri/ /textbook/index.html`（history 模式回退）；`location /api` 独立反代 Spring Boot（与"同域 /api 相对路径"约定不冲突）；
  - 小程序不受影响，baseUrl 仍单点配置。
- 小程序 `wx.request` 需要完整域名（微信平台限制，无法相对路径）：baseUrl 收敛到 `utils/config.js` **单一位置**，切环境只改这一处；微信后台合法域名随环境更新。
- 三套环境 `local` / `trial`(moonzj.com，阿里云 Ubuntu) / `school`（移交重部署）：差异仅存在于 env 文件与 Nginx 配置。
- HTTPS 必开（微信合法域名硬要求）；**部署手册为正式交付物**，含移交检查单——小程序移交学校流程：改 `utils/config.js` 域名 → 微信后台合法域名更新 → 重新提审 → 体验版回归（O8）。
- **兼容性矩阵（Q14）**：仅支持现代浏览器——Chrome / Edge 近两年版本、Firefox 最新稳定版；Vue 3 不支持 IE11，机房 IE11/360 兼容模式一律引导改用 Edge/Chrome，不做 polyfill。Web 端桌面优先、**不做响应式**，移动场景由小程序承接（E1）。〔待田老师确认机房浏览器，逾期按本条执行〕

## 3. RBAC 前端实现（锁定）

```
登录 → 拉取 /me/permissions（角色列表 + 权限码 + 数据范围）
  ① 路由守卫：beforeEach 校验 route.meta.permission，无权限 → 403
  ② 动态菜单：侧边栏由 permissions 过滤生成
  ③ 按钮级：~~v-perm="'order:export'" 指令，无码移除 DOM~~ **【已作废】** `v-perm` 属零引用死代码已删除，唯一机制是 `PermButton` 组件（`src/components/PermButton.vue`），无权限码**移除 DOM**。现口径见 `SPEC.md` §4.4
```

- 权限码以后端 `sys_permission` 为准，前端不写死角色名。
- 多角色（A4-A）：登录返回角色列表，个人中心可切换身份，切换后重拉菜单与数据。
- 数据隔离完全由后端执行，前端权限只管显示，不是安全边界。
- 首次登录（初始密码=学号/工号后 6 位，G1 定稿）强制改密弹窗，不可跳过。

### 3.1 会话管理（Q6 新增）

- JWT 双令牌：access 短时效 + refresh 轮转；refresh 端点与 401 错误码细分列入 **M1 契约冻结清单**（角色版本号机制 03 号文档 §3.3 已定）。

| 401 语义                    | 前端行为                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| access token 过期           | 静默 refresh，成功后重放原请求；并发 401 共享同一次 refresh、其余请求排队等待                     |
| refresh 失效 / 角色版本失效 | 强制登出跳登录页，提示「登录已过期，请重新登录」/「账号信息已变更，请重新登录」                   |
| 账号被停用                  | 强制登出跳登录页，提示「账号已停用，请联系教材室」——停用用户下一次请求即被踢，不等 token 自然过期 |

### 3.2 接口消费层规范（O3 新增，M1 任务）

- 单例 axios 实例 + 请求/响应拦截器；错误包络、分页参数（`page`/`size`）以 03 号文档 M1 契约（rest-api-conventions）为准，契约冻结日终定。
- 全局处理矩阵：401 按 §3.1 三类分流；403 由路由守卫重定向 403 页；409 关窗拦截给友好提示（S5/R8）；断网 / 5xx / 空态走统一提示文案令牌（对齐 `textbook-order-web/PRD.md` 功能 7）。
- **M1 契约冻结清单新增条目**：① JWT refresh 流程与 401 语义分类；② 字段审查错误逐字段回显格式（`field`/`rule`/`message`，O14）；③ `system_config` 数量上限读取接口（O14，教师填报表单预校验用）。

### 3.3 交互竞态规则（O13 新增）

1. 首登强制改密弹窗**先于**通知阻塞弹窗弹出——未改密不拉取业务数据（安全前置）。
2. `/notice/unconfirmed` 请求失败 = **fail-open**：放行进入，下次进入重查（对齐 Web PRD 功能 4 异常分支）。

## 4. 时间窗口引擎（前端视角，锁定）

- 全局状态 `windowStatus: 'not_open' | 'open' | 'closed'` + `windowEnd` 倒计时。
- 超管操作（自动到点开启/截止、手动开启/提前截止、无限次延长）→ 变更后所有端自动感知（进入页面拉取 + 全局横幅）。
- **延长/提前截止触发系统通知任务**：各端自动弹出通知（内容含本次延长时间与新截止时间、提醒尽快提交）——走第 5 节弹窗通道。
- open：填报/选购正常；closed：入口锁定 +「本期征订已截止，可查看历史记录」横幅；关窗后查看/导出不受影响。

## 5. 弹窗通知系统（锁定，替代站内信）

```
学生/教师打开小程序或 Web
→ 请求 /notice/unconfirmed
→ 有未确认通知 → 自绘居中阻塞 Modal 逐条弹出
→ 点「收到」→ POST /notice/{taskId}/confirm → 全部确认完毕才放行进入
→ 无未确认通知 → 直接进入
```

- 小程序端：点「收到」的同时调 `wx.requestSubscribeMessage` 请求下一轮订阅授权（为后台重发攒发送资格，这是订阅消息授权率的关键动作）。
- 首次进入小程序时引导授权一次；授权状态在「我的」页可查。
- 通知范围=秘书+教师+学生全量（G4 已拍板）：教师/秘书走同一弹窗通道，同样必须确认。
- **触达承诺（Q8 明示）**：教师/秘书仅弹窗触达（打开 Web 时拉取），**不保证必达**——短信有持续预算成本、订阅消息类目（个人主体）仅覆盖学生场景；学生 = 弹窗 + 订阅消息双通道。验收按此口径执行，不按"全量必达"。
- **轮次语义（Q7 修订）**：「每天 1 轮、最多 5 轮」仅约束**订阅消息重发通道**（推送通道，有授权配额成本）；弹窗是拉取通道（打开端请求一次，零边际成本），**不设轮次上限**——直到用户确认或超管手动关闭任务。`/notice/unconfirmed` 对已停止重发但未确认的任务**仍返回**。

**实现期偏离与决策记录**

1. **本地环境用 Vite 内置 `development` 模式**承载原 "local" 环境：Vite 禁止 `local` 作为 mode 名（与 `.env.local` 后缀冲突）。三套环境差异仍只在 env 与 Nginx：trial/school 用独立 env 文件，**本地开发无需任何 env 文件**（`vite.config.ts` 按模式取默认值：development → `base=/` + 挂 mock；显式配置优先）。
2. **阻塞通知弹窗改为自绘居中 Modal**（未用 el-dialog）：浏览器实测 el-dialog 离场过渡会滞留 `is-closing` 状态导致遮罩残留阻塞页面，与 PRD 功能 4「自绘居中 Modal」要求一致，改自绘后确认闭环可靠且已有测试固化覆盖。
3. **mock 阶段错误包络双约定兼容**：http 拦截器同时支持「HTTP 状态码」与「200 + 业务码」两种后端约定，M1 契约冻结后无需改动页面代码。
4. **导出文件在 mock 环境输出 CSV**（含 BOM，Excel 可直接打开），真实 xlsx 文件流由后端 M3 交付。
5. **mock 种子口令不落明文**：种子账号一律按 PRD 功能 1 / G1「初始密码 = 学号/工号后 6 位」派生校验（`mock/db.ts` 的 `initialPassword()`），仓库内不存在任何口令字面量；演示账号口令见 `README.md`。
6. **`.env` 文件不入库**：`.env` / `.env.development` 属安全扫描敏感文件清单，且本地开发无需 env 即可开箱运行，故删除；`.env.trial` / `.env.school`（无密钥）保留入库，`.gitignore` 补齐凭据类防御性条目。
